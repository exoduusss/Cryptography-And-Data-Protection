# Week 2: Double Ratchet & X3DH Protocol Specification

## 1. Cryptographic Primitives

The protocol utilizes audited cryptographic primitives from the Python `cryptography` library:
- **Curve25519 (X25519)**: Elliptic curve Diffie-Hellman key exchange (RFC 7748).
- **Ed25519**: Edwards-curve digital signatures for identity authentication (RFC 8032).
- **HKDF-SHA256**: HMAC-based Extract-and-Expand Key Derivation Function (RFC 5869).
- **ChaCha20-Poly1305**: Authenticated Encryption with Associated Data (AEAD, RFC 8439).
- **Scrypt / PBKDF2**: Password-based key derivation for at-rest state encryption.

## 2. Extended Triple Diffie-Hellman (X3DH) Handshake

Before establishing a Double Ratchet session, Alice initiates an X3DH exchange with Bob's prekey bundle fetched from the server.

### Key Definitions:
- $IK_A, IK_B$: Long-term Identity Keys (X25519 for DH, Ed25519 for signing).
- $SPK_B$: Signed Prekey published by Bob, signed with Bob's Ed25519 identity key.
- $OPK_B$: One-time Prekey published by Bob (optional, consumed once).
- $EK_A$: Ephemeral Key generated by Alice.

### Shared Secret Derivation:
Alice performs up to four DH agreements:
$$DH_1 = \text{X25519}(IK_A, SPK_B)$$
$$DH_2 = \text{X25519}(EK_A, IK_B)$$
$$DH_3 = \text{X25519}(EK_A, SPK_B)$$
$$DH_4 = \text{X25519}(EK_A, OPK_B) \quad \text{(if } OPK_B \text{ present)}$$

The Master Shared Key ($SK$) is derived via HKDF:
$$SK = \text{HKDF-SHA256}(DH_1 \parallel DH_2 \parallel DH_3 \parallel DH_4, \text{info}=\text{"X3DH-Master-Secret"})$$

## 3. Double Ratchet State Machine

The Double Ratchet combines two distinct ratchets:
1. **Symmetric KDF Chain Ratchet**: Advances with every message sent or received.
2. **Diffie-Hellman (DH) Ratchet**: Advances whenever a message with a new public key is received.

### Symmetric KDF Chain Step:
Given a chain key $CK$:
$$(CK_{i+1}, MK_i) = \text{HKDF-SHA256}(CK_i, \text{info}=\text{"Chain-Advance"})$$
where $MK_i$ is the single-use Message Key, and $CK_{i+1}$ replaces $CK_i$. The previous key $CK_i$ is immediately deleted to ensure **Forward Secrecy**.

### Diffie-Hellman Ratchet Step:
When Bob receives a message with a new DH public key $DH_{ratchet}$:
1. Derive new receiving chain key and next root key:
   $$(RK_{new}, CK_r) = \text{HKDF-SHA256}(RK_{prev}, \text{X25519}(DH_{priv}, DH_{ratchet}))$$
2. Generate a new local ephemeral DH pair: $(DH'_{priv}, DH'_{pub})$.
3. Derive new sending chain key and next root key:
   $$(RK_{next}, CK_s) = \text{HKDF-SHA256}(RK_{new}, \text{X25519}(DH'_{priv}, DH_{ratchet}))$$

This DH step provides **Post-Compromise Recovery** (Break-in Recovery).

## 4. Message Framing & Associated Data (AD)

Every ratchet message contains:
- **Header**:
  - `dh_pub`: Sender's current DH ratchet public key (32 bytes).
  - `pn`: Previous sending chain length (count of messages in previous chain).
  - `n`: Message index in current sending chain.
- **Ciphertext**:
  ChaCha20-Poly1305 ciphertext of plaintext payload.
- **Associated Data (AD)**:
  $$AD = \text{SerializeHeader}(Header) \parallel IK_A \parallel IK_B$$
The Poly1305 MAC validates both the header metadata and the payload. Any tampering with message numbers or keys causes decryption to fail.
